שיעור רשתות מתקדם: ACLs & NAT

למידה אינטראקטיבית, דיאגרמת רשת, סימולציות, תרגול Cisco, רפלקציה ומבחן מסכם

1. מהם ACLs Access Control Lists?

רשימת בקרת גישה ACL היא אוסף חוקים המשמש לסנון תנועת נתונים ברשת. ה-ACL קובע אילו חבילות מורשות Permit או נחסמות Deny בממשק הנתב או חומת האש על פי פרמטרים כגון כתובת IP מקור/יעד, סוג פרוטוקול, ומספרי פורטים.

  • סינון אבטחה: חסימת תנועה בלתי מורשית.
  • בקרת תנועה Segmentation: הפרדת רשתות ומחלקות.
  • ניתוב מבוסס מדיניות: תיעדוף נתונים.
  • שילוב עם NAT: הגדרת התנועה המורשית לתרגום כתובות.

2. אופן הפעולה ו-Implicit Deny

ה-ACL מוחל בכיוון נכנס Inbound - לפני הנתוב, או בכיוון יוצא Outbound - לאחר הנתוב. הבדיקה מתבצעת מלמעלה למטה לפי עיקרון First-Match-Wins:

  1. הנתב בודק כל שורה בסדר טורי.
  2. ברגע שנמצאה התאמה, הפעולה permit/deny מבוצעת מיד.
  3. אם לא נמצאה שום התאמה, מופעל חוק נסתר בסוף הרשימה:
deny ip any any

כלומר, כל תנועה שלא הורשתה במפורש - תיחסם כברירת מחדל.

3. Wildcard Mask - איך קוראים אותה?

בניגוד ל-Subnet Mask הרגילה, ה-Wildcard Mask הפוכה: הספרה 0 אומרת בדוק התאמה מדויקת בסיבית הזו, והספרה 1 אומרת התעלם מהסיבית הזו - כל ערך מתקבל.

מטרה כתובת רשת Wildcard Mask משמעות
מארח בודד 192.168.1.10 0.0.0.0 התאמה מדויקת - זהה ל-host 192.168.1.10
רשת /24 192.168.1.0 0.0.0.255 כל 254 המארחים ברשת 192.168.1.0/24
כל הכתובות - 255.255.255.255 זהה למילת המפתח any
💡 טיפ זיכרון: Wildcard Mask מתקבלת ע"י החסרת ה-Subnet Mask מ-255.255.255.255. לדוגמה: 255.255.255.255 - 255.255.255.0 = 0.0.0.255.

4. סוגי ACLs עיקריים

סוג ACL טווח מזהה פרמטרי סינון שימוש נפוץ
Standard Numbered 1-99 / 1300-1999 IP מקור בלבד בקרת גישה בסיסית, אבטחת גישת VTY
Standard Named שם טקסטואלי IP מקור בלבד קריאות גבוהה ועריכה נוחה של שורות
Extended ACL 100-199 / 2000-2699 מקור, יעד, פרוטוקולים TCP/UDP/ICMP ופורטים סינון פרטני, הגנת שרתים, חומות אש
Resequencing פקודת מערכת סידור מחדש של מספרי שורות ב-ACL הכנסת חוקים חדשים בין שורות קיימות

5. תרחישי Extended ACL נפוצים

  • תרחיש 1: חסימת Telnet לכולם למעט אדמין:
access-list 110 permit tcp host 192.168.1.100 any eq 23
access-list 110 deny tcp any any eq 23
access-list 110 permit ip any any
  • תרחיש 2: אישור גלישת Web בלבד HTTP / HTTPS:
access-list 120 permit tcp 10.0.0.0 0.0.0.255 any eq 80
access-list 120 permit tcp 10.0.0.0 0.0.0.255 any eq 443
access-list 120 deny ip any any
  • תרחיש 3: אישור Ping ICMP רק משרת ניטור NOC:
access-list 130 permit icmp host 172.16.1.10 any
access-list 130 deny icmp any any
access-list 130 permit ip any any

6. כיוון ה-ACL ומיקומו הנכון בטופולוגיה

שאלת איפה מדביקים את ה-ACL היא אחת השאלות הנפוצות ביותר במבחני CCNA, ויש לה כלל אצבע פשוט:

Standard ACL
➜
קרוב ליעד Destination
Extended ACL
➜
קרוב למקור Source

ההיגיון: Standard ACL בודק רק כתובת מקור, ולכן אם נמקם אותו קרוב מדי למקור - עלול לחסום תנועה לגיטימית ליעדים אחרים. Extended ACL לעומת זאת בודק גם מקור וגם יעד, ולכן כדאי לחסום אותו כמה שיותר קרוב למקור - כדי לחסוך רוחב פס מיותר ברשת.

7. כתובות IP פרטיות RFC 1918 ו-NAT

כתובות פרטיות אינן מנותבות באינטרנט הציבורי. מנגנון NAT מתרגם אותן לכתובות ציבוריות:

Class טווח כתובות פרטיות RFC 1918 Subnet Mask / CIDR
Class A 10.0.0.0 – 10.255.255.255 255.0.0.0 /8
Class B 172.16.0.0 – 172.31.255.255 255.240.0.0 /12
Class C 192.168.0.0 – 192.168.255.255 255.255.0.0 /16

8. מונחי NAT: Inside/Outside, Local/Global

לפני שמגדירים NAT, חשוב לדעת לקרוא לכל כתובת בשמה הנכון - זה בדיוק מה שנשאלים במבחנים ובראיונות עבודה:

מונח הגדרה דוגמה
Inside Local הכתובת הפרטית של המארח הפנימי, כפי שהיא נראית בתוך הרשת המקומית 192.168.1.10
Inside Global הכתובת הציבורית שאליה תורגמה כתובת המארח הפנימי, כפי שהיא נראית מבחוץ 200.1.1.10
Outside Global הכתובת הציבורית האמיתית של השרת ביעד, כפי שהוגדרה ע"י בעליה 8.8.8.8
Outside Local איך כתובת היעד החיצוני נראית מנקודת המבט של הרשת הפנימית ברוב המקרים זהה ל-Outside Global 8.8.8.8

9. סוגי NAT Network Address Translation

סוג NAT סוג מיפוי שימוש בפורטים שימוש עיקרי
Static NAT מיפוי 1-ל-1 קבוע בין IP פרטי לציבורי לא אירוח שרתים Web/Mail לגישה מבחוץ
Dynamic NAT מיפוי רבים-לרבים מתוך מאגר Pool לא גישה זמנית לאינטרנט עד גמר המאגר
PAT NAT Overload מיפוי רבים-ל-1 תוך שימוש במספרי פורטים כן חיבור מאות/אלפי משתמשים ל-IP ציבורי יחיד

פקודות בדיקה ואימות NAT ב-Cisco:

show ip nat translations  ! הצגת טבלת התרגומים הפעילים
show ip nat statistics    ! הצגת סטטיסטיקות Hits, Misses, Pools
clear ip nat translation * ! ניקוי טבלת התרגומים

10. סדר הפעולות: איך ACL ו-NAT מדברים זה עם זה

שילוב שגוי בין ACL ל-NAT הוא אחד הבאגים הנפוצים ביותר בפועל. הכלל החשוב ביותר לזכור:

חבילה נכנסת מהרשת הפנימית
➜
ACL Inbound
➜
NAT Inside → Outside
➜
יוצאת לאינטרנט

כלומר, כאשר ה-ACL וה-NAT מוגדרים על אותו ממשק פנימי, ה-ACL נבדק לפני תרגום הכתובת. משמעות הדבר: כללי ה-ACL חייבים להתייחס לכתובות ה-Inside Local הפרטיות, ולא לכתובות המתורגמות. טעות נפוצה של תלמידים היא לכתוב חוק ACL לפי הכתובת הציבורית - וזה פשוט לא יעבוד.

יישום ACLs & NAT בסביבות ארגוניות שונות

1. עסק קטן

  • ACLs: מימוש בסיסי על נתב הקצה או מתג L3. שימוש ב-Standard ACLs להגבלת גישה לניהול ו-Extended ACLs לבקרת Wi-Fi אורחים.
  • NAT: שימוש ב-PAT NAT Overload על נתב הקצה ליציאת כל העובדים לרשת, בצורת Static NAT בודד אם קיים שרת מקומי.

2. ארגון גדול

  • ACLs: שימוש נרחב ב-Extended ACLs הפרדה קפדנית בין מחלקות, VLANs, וסגמנטים של הדאטה סנטר. שילוב מול מערכות Identity כגון Cisco ISE / Active Directory.
  • NAT: יתירות HSRP/VRRP, שילוב Static NAT, Policy NAT ו-NAT Exemption עבור מנהרות VPN סניפיות.

3. מרכז נתונים

  • ACLs: מיקרו-סגמנטציה Microsegmentation, בידוד דיירים Tenant Isolation מבוסס SDN / Cisco ACI. החלת חוקים קרוב ככל הניתן למקור.
  • NAT: הימנעות מ-NAT בתוך ליבת הדאטה סנטר לשמירה על שקיפות וניטור. ביצוע NAT אך ורק בהיקף Perimeter.

סימולציה 1: מסע החבילה דרך ה-ACL

בחר מאפייני חבילה, שלח אותה, וצפה כיצד היא עוברת שורה אחר שורה ברשימת ה-ACL עד למציאת ההתאמה הראשונה עקרון First-Match-Wins. הרשימה המדומה כאן היא ACL מס' 110 מהתרחיש שלמדנו חסימת Telnet לכולם למעט אדמין.

שאלות רפלקציה ולמידה עצמית

כתוב את תשובותיך בתיבות הטקסט. התשובות נשמרות אוטומטית במכשיר שלך.

מורה תשובות מומלצות לשאלות הרפלקציה

תשובות מפורטות ומדויקות לשאלות הרפלקציה

  1. משמעות המיקום Standard ACL מול Extended ACL:
    חוקי ה-Standard ACL בודקים אך ורק את כתובת ה-IP של המקור Source IP. אם נמקם אותם קרוב למקור, הנתב יחסום את המחשב מלהוציא תנועה בכלל - גם ליעדים מורשים אחרים ברשת. לכן, מציבים אותם קרוב ככל הניתן ליעד Destination.
    לעומת זאת, Extended ACL בודק כתובת מקור, כתובת יעד, פרוטוקול ופורט. מאחר שיש לנתב את כל המידע הנדרש כדי לקבל החלטה מדויקת, נעדיף לחסום תנועה בלתי מורשת קרוב ככל הניתן למקור Source כדי למנוע ממנה לעבור בנתבים נוספים ולבזבז רוחב פס יקר ברשת.

  2. סכנת ה-Implicit Deny:
    בסוף כל ACL מופעל חוק נסתר אוטומטי של deny ip any any. אם נגדיר ACL שיש בו רק שורת deny אחת למשל חסימת מחשב מסוים, כל חבילה אחרת שתגיע ולא תתאים לשורה הזו - תמשיך לשורה הנסתרת בסוף ותחסם גם כן! כתוצאה מכך, כל התנועה בממשק תיחסם לחלוטין.
    כדי למנוע זאת, חייבים להוסיף שורת אישור מפורשת בסוף הרשימה, כגון permit ip any any.

  3. שיקולי Static NAT מול PAT NAT Overload:
    נשתמש ב-Static NAT תרגום קבוע 1-ל-1 כאשר אנו מארחים שרת פנימי בארגון כגון שרת Web, שרת דואר SMTP, או שרת VPN שצריך להיות נגיש באופן קבוע ויזום על ידי משתמשים מכל רחבי האינטרנט דרך כתובת IP ציבורית קבועה וידועה מראש.
    לעומת זאת, נשתמש ב-PAT עבור כל תחנות הקצה של המשתמשים בארגון, המזמינים תקשורת רק בכיוון היוצא החוצה לאינטרנט.

  4. אתגר הדיבאגינג Debugging & Troubleshooting:
    הפקודות המרכזיות להרצה על הנתב לחקירת הבעיה הן:
    • show ip access-lists – לבדוק האם ממוני הראיות של חוקי ה-ACL עולים בעת ניסיון גלישה בפורט 443 HTTPS, והאם קיים חוק deny שבטעות חוסם תנועה זו.
    • show ip nat translations – לבדוק האם נוצרות שורות תרגום פעילות עבור הכתובות הפרטיות בפורט 443 בטבלת ה-NAT.
    • show ip nat statistics – לבדוק האם הממשקים הוגדרו נכון כ-inside ו-outside, והאם יש גידול במספר ה-Misses או שרשימת ה-ACL של ה-NAT תקינה.

מבחן מסכם - 10 שאלות רב-ברירה

ענה על כל שאלה ולחץ על בדוק תשובה לקבלת משוב מיידי. בסיום כל השאלות תוצג לך תוצאה כוללת.

ציון נוכחי: 0 / 10
מורה תשובות מפורטות ל-10 שאלות המבחן

תשובות מלאות ומוסברות למבחן המסכם

  1. שאלה 1: deny ip any any Implicit Deny – בסוף כל ACL מופעל חוק נסתר החוסם כל תנועה שלא הותר במפורש.
  2. שאלה 2: קרוב ככל הניתן ליעד – מאחר ש-Standard ACL בודק רק מקור, מיקום קרוב ליעד מונע חסימה לא מוצדקת ליעדים אחרים.
  3. שאלה 3: קרוב ככל הניתן למקור – Extended ACL בודק גם מקור וגם יעד, ולכן חסימה מוקדמת חוסכת רוחב פס ברשת.
  4. שאלה 4: 100-199 – טווח המסיכום המיועד ל-Extended Numbered ACLs.
  5. שאלה 5: show ip nat translations – הפקודה המציגה את טבלת התרגומים הדינמית/סטטית של ה-NAT.
  6. שאלה 6: מיפוי רבים-ל-1 תוך הבחנה בין המארחים באמצעות מספרי פורטים – זהו העיקרון של PAT Overload.
  7. שאלה 7: Static NAT – יוצר תרגום קבוע 1-ל-1 שמתאים במיוחד לאירוח שרתים.
  8. שאלה 8: 10.0.0.0 – 10.255.255.255 – טווח הכתובות הפרטיות התקני של Class A לפי RFC 1918.
  9. שאלה 9: לסמן אילו סיביות בכתובת ה-IP ייבדקו בהתאמה מדויקת 0 ואילו יתעלמו 1 – הגדרת ה-Wildcard Mask.
  10. שאלה 10: כדי לשמור על שקיפות התנועה ולאפשר ניטור פשוט ומדויק – סיבת הימנעות מ-NAT בליבת הדאטה סנטר.
